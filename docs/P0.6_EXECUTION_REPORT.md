## 3. Implementaciones Realizadas por Bloque de Trabajo

### Bloque A: Endurecimiento de Promoción y Rollback
1. **Auditoría Diferencial Granular de Avisos (`scripts/compare-audit-advisories.js`):**  
   Se corrigió el defecto de restar totales globales de vulnerabilidades. El nuevo comparador analiza avisos individuales por identificador (`GHSA` o clave compuesta), paquete afectado, rango y severidad. Clasifica en: preexistentes, recién introducidas, resueltas, severidad alterada o indeterminadas. Bloquea la promoción si se introduce cualquier vulnerabilidad nueva o si el reporte es indeterminado por fallos de red.
2. **Autoverificación Criptográfica de Respaldos (Gate 1):**  
   Se incorporó en el Runbook la comprobación de no pre-existencia del destino y una verificación post-copia que contrasta los hashes SHA-256 de todos los archivos respaldados contra el inventario de Gate 0.
3. **Rollback Multinivel Verificable:**  
   Se diseñó la reversión en 6 fases controladas con emisión de `promotion_abort_evidence.json` y verificación de versión final.
4. **Delimitación de Almacenamiento:**  
   Se documentó formalmente que el respaldo de `.openmemory/` cubre archivos JSON y Markdown y **no** garantiza la consistencia de una base SQLite activa.

### Bloque B: Batería de Promoción en Consumidor Sintético
* **Suite Automatizada (`.work/experiments/test-synthetic-consumer-promotion.js`):**  
  Implementación de un arnés que simula un consumidor externo con datos propios y base SQLite simulada en un directorio temporal aislado (`om-p06-synthetic-consumer-*`).
  Ejecuta los Gates 0 al 4:
  - Gate 0: Inventario criptográfico inicial.
  - Gate 1: Creación de respaldo con comprobación de no pre-existencia y autoverificación criptográfica.
  - Gate 2: Instalación de `openmemory-0.3.14-rc4.tgz` en el consumidor sintético.
  - Gate 3: Carga de exports públicos (6/6), inicialización de servidor MCP con 29 herramientas, persistencia con `withStateLock` y verificación de limpieza de paquete (0 fuentes/tests filtrados).
  - Gate 4: Inducción de fallo de estado, ejecución de rollback y comprobación de paridad criptográfica del 100% contra el inventario de Gate 0.
