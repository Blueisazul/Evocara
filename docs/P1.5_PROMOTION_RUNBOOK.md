## 4. Procedimiento de Rollback de Emergencia

### A. Rollback Automático (Gestionado por el Motor)
Si durante la Fase 3, 4 o 5 ocurre cualquier excepción o el smoke test falla:
1. El motor captura el error y activa inmediatamente `executeRollback()`.
2. Restaura `.openmemory/` desde el respaldo verificado utilizando un área de staging transitoria.
3. Reinstala el paquete original `openmemory@0.3.1` desde la referencia previa.
4. Comprueba bidireccionalmente la paridad criptográfica de los archivos restaurados.
5. Escribe la evidencia forense completa en `backups/promotion_abort_evidence.json`.
6. Libera el bloqueo y devuelve código de salida `EXIT 1`.

### B. Rollback Manual (Si el Proceso es Abruptamente Interrumpido)
Si ocurre una pérdida de energía o terminación de proceso (`SIGKILL`) durante la instalación:
1. **Verificar el archivo de lock:** Si existe `InventoryHub/.promotion.lock`, examinar el archivo para conocer el ID de promoción.
2. **Localizar el Respaldo Más Reciente:**
   Examinar `InventoryHub/backups/backup_promo_*`.
3. **Restaurar el Directorio de Estado:**
   ```bash
   # Eliminar directorio potencialmente corrupto
   rmdir /S /Q "C:\Users\sant1\OneDrive\Documentos\ChatGPT\OpenMemory\InventoryHub\.openmemory"
   # Copiar el respaldo íntegro
   xcopy /E /I /H /K "C:\Users\sant1\OneDrive\Documentos\ChatGPT\OpenMemory\InventoryHub\backups\backup_promo_<ID>\.openmemory" "C:\Users\sant1\OneDrive\Documentos\ChatGPT\OpenMemory\InventoryHub\.openmemory"
   ```
4. **Restaurar la Dependencia en `package.json`:**
   Asegurar que la entrada señale a `file:scratch/exp2_10/fase4_5/dist/openmemory-0.3.1.tgz`.
5. **Reinstalar Dependencias Originales:**
   ```bash
   cd "C:\Users\sant1\OneDrive\Documentos\ChatGPT\OpenMemory\InventoryHub"
   npm install --no-audit
   ```
6. **Limpiar Lock Residual:** Eliminar manualmente `InventoryHub/.promotion.lock`.
