## 2. Compatibilidad Técnica de Versiones de Node.js

Se evaluó la compatibilidad de cada versión de Node.js con los requisitos del proyecto:

* **`package.json` Declaración:** `"engines": { "node": ">=18.0.0" }`.
* **Node 18 (LTS v18.x):**
  - Soporte nativo de `node:crypto` con algoritmos SHA-256 / HMAC.
  - Soporte nativo de Web Streams y `node:fs/promises`.
  - Limitación conocida: No cuenta con `crypto.subtle` completamente alineado con la especificación WebCrypto sin flags en revisiones muy tempranas, pero la biblioteca utiliza la API nativa de Node `crypto.createHash()`, 100% compatible.
* **Node 20 (Active LTS v20.x):**
  - Entorno de referencia actual de calificación y pruebas.
  - Compatibilidad total comprobada con las 14 suites oficiales.
* **Node 22 (Current v22.x):**
  - Soporte completo para ESM nativo y APIs de filesystem sincrónicas y asincrónicas.
  - `require()` síncrono para módulos ESM disponible, sin impacto adverso en CommonJS/ESM híbrido de OpenMemory.
  - Comportamiento de `fs.renameSync` con reemplazo atómico en POSIX idéntico a Node 20.

**Veredicto de Compatibilidad:** Las 9 combinaciones son técnicamente viables y no presentan incompatibilidades semánticas con el código compilado ni con las dependencias del proyecto.

## 3. Estructura de Seguridad y Mínimos Permisos del Workflow

El archivo `.github/workflows/ci.yml` fue reconfigurado para respetar estrictamente el principio de mínimo privilegio:

```yaml
permissions:
  contents: read
  id-token: write      # Requerido exclusivamente para atestación criptográfica OIDC
  attestations: write  # Requerido para firmar la atestación de procedencia de build
```

### Características de Seguridad:
1. **Sin Credenciales Persistentes:** No se inyectan tokens de publicación de npm (`NPM_TOKEN`) ni credenciales SSH permanentes en los jobs de verificación.
2. **Checkout Inmutable:** Uso de `actions/checkout@v4` con persistencia desactivada en pasos de prueba.
3. **Instalación Segura:** Ejecución condicional de `npm ci` (cuando existe lockfile) o `npm install --ignore-scripts` seguido de compilación controlada, previniendo la ejecución de scripts maliciosos de terceros en tiempo de instalación (`postinstall` hooks).
4. **Captura Forense de Evidencia:** Paso condicional `if: failure()` para archivar trazas, logs de eventos y volcados de estado en caso de error.

## 4. Pipeline de Verificación por Runner

Cada runner en la matriz ejecuta la siguiente secuencia inmutable:

1. **Checkout Limpio:** Clon del árbol de trabajo sin estado residual.
2. **Setup Node:** Inicialización de la versión correspondiente de Node.js con caché de npm activada.
3. **Instalación Reproducible:** Instalación de dependencias de desarrollo.
4. **Compilación TypeScript:** `npm run build` generando `dist/` sin errores de tipado (`tsc`).
5. **Ejecución de Suites Oficiales:** `node scripts/safe-test-runner.js` ejecutando las 14 suites oficiales:
   - `SEC-001`, `PERSIST-001`, `F13.3.3`, `SPIKE`, `AUDIT-COMPARE`
   - `SYNTHETIC-PROMO`, `RECOVERY-P08`, `RECOVERY-P09`, `INVARIANTS-P10`
   - `TRANS-BACKUP`, `ADVERSARIAL-P12`, `REHEARSAL-P13`, `HARDENING-P14`
   - `ADVERSARIAL-P15` (Nueva suite P1.5)
6. **Verificación de Empaquetado:** `node scripts/ci-verify-package.js`.
   - Simulación de `npm pack`.
   - Inspección estricta de whitelist (21 archivos de distribución).
   - Detección de fugas de fuentes (`src/`), tests (`test/`, `__tests__`) y archivos de trabajo (`.work/`, scratch).
   - Generación del tarball en sandbox aislado y comparación bit-a-bit contra `af88fae90107dfda797c7f6bcc982cf6bbd7ef53fd9a5d887c9bf77185a35f6e`.
7. **Verificación de SBOM CycloneDX:** `node scripts/generate-sbom.js --validate`.
8. **Verificación de Manifiesto de Release:** `node scripts/generate-release-manifest.js --validate`.
9. **Atestación de Procedencia de Build (Solo en release/tag):** Invocación de `actions/attest-build-provenance@v2` para generar atestación criptográfica respaldada por GitHub OIDC.

* **Motivo del Bloqueo:** La ejecución de GitHub Actions requiere un `git push` a la rama remota, operación que excede los límites de autorización autónoma local de P1.5.
* **Preparación Completa:** El workflow, scripts, suites y validadores están 100% listos para ejecutarse inmediatamente tras la autorización humana del push.
