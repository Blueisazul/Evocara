## 3. Key Architectural Decisions & Rationale

| Architectural Decision | Context & Alternative Considered | Chosen Rationale & Security Benefit |
| :--- | :--- | :--- |
| **Commit `package-lock.json`** | Keep in `.gitignore` to avoid perceived risk to library consumers. | `npm pack` strictly ignores lockfiles by design. Committing it eliminates CI runner drift and non-deterministic dependency resolution across Node versions. |
| **Node.js 18 Legacy Tier Distinction** | Remove Node 18 from matrix vs keep with caveats. | Retain Node 18 in matrix for backward-compatibility validation. OpenMemory core has 0 runtime dependencies and runs cleanly; devDependency toolchain engine warnings (`ini@7.0.0`) are documented as non-fatal. |
| **SLSA Attestation Gating** | Generate attestation concurrently vs strictly sequential. | Strictly sequential: attestation requires 100% test pass across all 9 matrix runners. No token write permissions are granted to test jobs. |
| **Staged Directory Rollback with Double-Fault Quarantine** | Direct in-place rollback vs atomic staging swap. | In-place rollbacks can corrupt state if interrupted midway. Staging in an isolated directory with atomic swap prevents partial restorations and guarantees forensic preservation if double-faults occur. |
