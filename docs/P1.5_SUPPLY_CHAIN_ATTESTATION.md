## 5. Investigación sobre Lockfile y Modelo de Distribución

### Diagnóstico del Lockfile:
En el repositorio canónico, `package-lock.json` se encuentra excluido por convención en `.gitignore` para permitir la resolución flexible de dependencias en bibliotecas y plugins (`lib` model). Sin embargo, esto plantea un desafío de reproducibilidad estricta en pipelines de integración continua.

### Solución Diseñada para OpenMemory:
1. **Modo Biblioteca (Consumers):** Los consumidores finales (`InventoryHub`) controlan su propio árbol de dependencias mediante sus respectivos lockfiles.
2. **Modo Release Pipeline:** Durante la compilación de releases oficiales, el workflow de GitHub Actions ejecutará `npm install --package-lock-only` para congelar el árbol exacto de resolución y archivar dicho `package-lock.json` junto con el SBOM y la atestación.
3. **Validación de Empaque:** `ci-verify-package.js` comprueba que ningún archivo `package-lock.json` o `npm-shrinkwrap.json` contamine el tarball distribuible.

## 6. Atestación Criptográfica con GitHub Actions y OIDC

Para alcanzar **SLSA Build Level 2 y Level 3**, se implementó en `.github/workflows/ci.yml` la integración con el servicio oficial de atestación de GitHub:

```yaml
- name: Attest Build Provenance
  uses: actions/attest-build-provenance@v2
  with:
    subject-path: 'openmemory-*.tgz'
```

### Garantías Criptográficas de la Atestación GitHub:
* **Firma sin Llaves Privadas Locales (Keyless Signing):** Utiliza Fulcio (Sigstore) y tokens OIDC de GitHub Actions de corta duración.
* **Registro de Transparencia:** La atestación se publica en Rekor, garantizando que el origen del binario es inmutable e infalsificable.
* **Verificación de Consumidor:** Cualquier consumidor podrá validar la procedencia utilizando GitHub CLI oficial:
  ```bash
  gh attestation verify openmemory-0.3.14-rc4.tgz --owner sant1
  ```
