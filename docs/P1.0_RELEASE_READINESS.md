## 1. Taxonomía de Decisión de Release

Para garantizar una gobernanza rigurosa y auditable, cada criterio se evalúa bajo cuatro estados inequívocos:
- **PASS:** Requisito verificado empíricamente con evidencia reproducible.
- **FAIL:** Defecto confirmado o regresión detectada.
- **BLOCKED:** Acción pendiente de permiso, entorno o dependencia externa fuera del alcance autónomo.
- **INDETERMINATE:** Evidencia insuficiente para determinar conformidad de forma concluyente.

3. **GO para Crear o Distribuir Release (`git tag` / NPM publish):** **BLOQUEADO**  
   *Justificación:* Estrictamente condicionado a la aprobación de los 9 jobs de CI remota en GitHub Actions.
4. **GO para Promover en InventoryHub (Entorno Local Controlado):** **BLOQUEADO**  
   *Justificación:* Requiere orden explícita y supervisión humana tras la validación de la CI remota.
5. **GO para Despliegue en Producción:** **BLOQUEADO**
